# F1C — Retrieval & Skala (sisa item: FTS5, Float32 BLOB, dedupe SQL, list perf)

## Context

Roadmap Memoria sudah di v0.5.0 dengan F0/1A/1B/F2 selesai. Sisa F1C (backlog item 3 di `ROADMAP.md`): keyword search masih loop JS per-dokumen (`allMemories()` + fuzzy per kata, `search.ts:89-116`), embedding disimpan sebagai JSON TEXT dan `JSON.parse` dijalankan untuk **setiap baris di setiap `readMemories()`** (`db.ts:593`), dedupe melakukan full-scan `allMemories()` (`dedupe.ts:51`), dan list memori di web me-render penuh tanpa pagination di path draft/archive/tag. Acceptance F1C: 5.000 memori → search < 100 ms. Kerja di branch `feat/f1c-retrieval-scale` sesuai konvensi repo (merge commit ke main).

Fakta kunci dari eksplorasi: driver adalah **`node:sqlite` DatabaseSync** (bukan better-sqlite3), tidak ada mekanisme migrasi versi skema (hanya `PRAGMA table_info` + ALTER di `db.ts:125-153`), `memories.id` adalah `INTEGER PRIMARY KEY AUTOINCREMENT` (rowid alias — syarat FTS5 external-content), dan `updateMemory()` bisa mengubah `content` (edit modal) sehingga FTS butuh trigger UPDATE.

## 1. Migrasi skema berbasis `user_version` (`src/engine/store/db.ts`)

Introduksi pattern migrasi baru (pertama kali ada):
```ts
const MIGRATIONS: Array<(d: DatabaseSync) => void> = [m1Fts, m2EmbedBlob];
// di initDb, setelah migrate(): baca PRAGMA user_version, jalankan MIGRATIONS[v..], tulis ulang user_version
```
- **M1 — FTS5**: `CREATE VIRTUAL TABLE memories_fts USING fts5(content, content='memories', content_rowid='id')` + 3 trigger sync (`AFTER INSERT`, `AFTER DELETE`, `AFTER UPDATE OF content` — pola 'delete'/'insert' external-content standar). Backfill sekali via `INSERT INTO memories_fts(memories_fts) VALUES('rebuild')` (aman dibungkus IF-guard agar idempotent).
- **M2 — Float32 BLOB**: baca semua baris `embedding` yang masih TEXT/JSON, `JSON.parse` → `Buffer.from(Float32Array.from(v).buffer)` → UPDATE balik ke kolom yang sama (SQLite dynamically typed). Baris yang gagal parse di-skip.
- **Index baru** (di blok DDL utama, IF NOT EXISTS): `idx_memories_active ON memories(archived, status)` dan `idx_transcripts_pending ON transcripts(extracted, ts)`; `DROP INDEX IF EXISTS idx_transcripts_extracted` (tercakup composite). Migration M1 bisa memuat index memories ini.

Langkah implementasi pertama: verifikasi FTS5 aktif di node:sqlite lokal (`node -e` satu-liner dengan DatabaseSync `:memory:`) — kalau ternyata tidak ada, stop dan laporkan sebelum lanjut.

## 2. Search FTS5 + rerank (`src/engine/retrieve/search.ts`)

- `searchMemories()`: bangun FTS query dari token `keywordScore` yang sudah ada (token di-quote `"tok"*` untuk prefix, escape `"` ganda; AND antar token → fallback OR kalau kosong). Kandidat via:
  ```sql
  SELECT m.id, m.kind, m.content, ... FROM memories_fts f JOIN memories m ON m.id = f.rowid
  WHERE memories_fts MATCH ? AND m.archived = 0 AND m.status = 'active' [+ project_id/kind]
  ORDER BY bm25(memories_fts) LIMIT 200
  ```
  (`projectSlug` di-resolve ke id sekali, bukan per-baris). Kandidat lalu **rerank dengan `keywordScore` yang tetap dipakai** → formula blend existing tidak berubah (kw*0.5 + sem*0.3 + importance + recency + centrality).
- **Fallback path**: token kosong, MATCH error, atau hasil FTS 0 baris → jalankan loop legacy `allMemories()` yang sekarang (dipertahankan), sehingga perilaku tidak pernah lebih buruk dari sebelumnya.
- `projectContext()` & `weekly.ts` tidak diubah (bukan hot path query).

## 3. Embedding Float32 BLOB (`db.ts`, `vecfind.ts`, `insertMemory`)

- `insertMemory` (`db.ts:362`): tulis `Buffer.from(Float32Array.from(m.embedding).buffer)` — kompatibel karena kolom tetap `embedding`.
- `readMemories` (`db.ts:593`): decode BLOB → `new Float32Array(buf.buffer.slice(buf.byteOffset, buf.byteOffset + buf.byteLength))`; tetap `number[]` di tipe `Memory` (copi via Array.from bila perlu untuk kompatibilitas tipe).
- `vecfind.ts` rebuild (`:44`) & query `dialectCount` (`:18`): ganti `JSON.parse` dengan decode Float32; ubah predikat `embedding != ''` → `length(embedding) > 0` (perbandingan BLOB vs TEXT).
- Hasil: tidak ada lagi JSON.parse vektor di jalur baca manapun.

## 4. Dedupe kandidat via SQL (`src/engine/extract/dedupe.ts`)

- Ganti `allMemories().filter(...)` (`:51-55`) dengan query kandidat langsung: `WHERE archived = 0 AND status='active'` + (jika `m.projectId != null`) `AND project_id = ?` + (jika hasEmb) `AND embedding IS NOT NULL AND length(embedding) > 0 AND COALESCE(embed_model,'') = ?`, `ORDER BY created_at DESC LIMIT 500` (index `idx_memories_active` menopang).
- Logika similarity (cosine / Jaccard `textSimilarity`), threshold, merge, `linkNew`, `emitEvent` **tidak diubah**.

## 5. Web list perf (`src/engine/http.ts`, `web/app.js`, `web/index.html`)

- **Server pagination untuk path yang belum**: `/api/memories/list` (`http.ts:237-246`) dan `/api/memories/tag` (`http.ts:498-503`) terima `limit`/`offset` (clamp 1–200, default 50) dan balas bentuk sama dengan `/api/memories`: `{ memories, total, offset, limit, hasMore }`.
- **Client** (`app.js`): path draft/archive/tag memakai pola `memPagination` + tombol "Load more" yang sudah ada (string i18n "Load more" sudah terdaftar); filter kind/project/q tetap client-side di atas halaman yang termuat.
- **Event delegation**: `bindRowActions` (`app.js:567-655`) diganti satu delegated listener per kontainer list (baca `data-del/data-appr/data-edit/...` dari `e.target.closest('[data-...]')`) — hilangkan re-bind O(n) tiap render.
- **CSS-only windowing**: `.mem { content-visibility: auto; contain-intrinsic-size: auto 72px; }` di `web/index.html` — card di luar viewport skip render, aman untuk tinggi variabel (line-clamp 2 + expand).
- Jalankan `npm run check:ui` setelah edit (guard struktural baru).

## 6. Test & benchmark

- Perluas `tests/core.test.mjs` (node:test, zero-dep, jalankan terhadap `dist/`): fixture DB baru dengan `initDb(fs.mkdtempSync(path.join(os.tmpdir(), "memoria-test-")))`. Tambah kasus: (a) BLOB roundtrip — insertMemory dengan embedding → memoryById → cosine tetap benar; (b) migrasi DB lama — buat baris embedding JSON-TEXT manual, jalankan initDb ulang → terbaca sebagai vektor; (c) FTS — search ketemu kata persis & prefix, query typo tetap lewat rerank keywordScore, arsip/draft tidak ikut; (d) dedupe — duplikat teks merge (bukan insert), beda proyek tidak tergabung.
